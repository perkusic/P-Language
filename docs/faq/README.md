# Maintaining the student FAQs

Student entry point: `index.html`. Edit the two project-specific Markdown files,
not the generated HTML. `FAQ.md` is the chooser page. The project specifications
and assignments remain authoritative; a FAQ must not introduce assessment tasks.

## Build

Use Node 20 or newer and **marked 17.0.5**, pinned in `package.json`:

```text
cd docs/faq
npm install
npm run build
```

If marked 17.0.5 is already installed elsewhere, from the repository root:

```text
node docs/faq/build.cjs /absolute/path/to/node_modules/marked
```

The renderer checks that version and produces `index.html`,
`manufacturing-cell.html` and `robot-fleet.html`. Rebuilding with identical inputs
and that renderer must leave the generated bytes unchanged. Never regenerate the
project specifications as a side effect of building the FAQs.

## Shared-answer checklist

The pages intentionally have separate sources so that project-specific contracts
and assessed work can differ. When editing one of the following topics, review its
counterpart too; do not copy an answer without checking each project's requirements.

| Topic | Cell question | Fleet question |
| --- | --- | --- |
| Getting started and normative concepts | 1–13 | 1–13 |
| Expected failures and run records | 20–23 | 22–25 |
| L1, R3/S2, L2/L3/R2 and log monitoring | 24–28 | 26–30 |
| Scope and reporting | 29–30 | 31–32 |

In particular, keep these differences:

- Cell clearance: AGV fully outside, or all arm moving parts retracted; the base
  never enters. Fleet clearance: the whole mobile robot clears the prior zone.
- R2 calibration is part of the cell assignment. Do not add it as a separate
  fleet deliverable.
- Cell examples use jobs, transfer zone, technician and S4. Fleet examples use
  deliveries, corridor zones, bays and sanction fairness.
- The fleet's cause-aware F1 monitor is required; comparison by refinement with
  an abstract centralized regulator is a separate stretch goal.

## Navigation and interaction

Question IDs are derived from the English question text **without its displayed
number**. Inserting or renumbering questions therefore preserves existing HTML
links. Editing a question's wording can change its ID and break an existing deep
link. The builder does not support ID aliases. After changing a published or
shared question's wording, update the affected references and give readers the
new link; preserving an old ID would require a separate change to the builder.

Check both pages after changes: project links and section anchors, deep links,
search and restoration of open answers, hiding sections with no matches, phone
width, keyboard access and light/dark themes. Test the terms suggested by each
page's search placeholder.
